User Story: Product Sharing Across Modules
Objective: Implement a shared ProductManager Class that maintains real-time synchronization
of product data across all modules.
Inputs
1. Product Data Input (from Seller)
○ Product Name: String (1-100 characters, non-empty)
○ Price: Double (minimum 0.01, maximum 999999.99)
○ Stock Quantity: Integer (0 or positive)
○ Category: String (Electronics, Accessories, Office, Other)
○ Description: String (0-500 characters, optional)
○ Seller ID: String (non-empty, existing seller)
2. Product Operation Requests
○ Add Product: ProductManager.addProduct(Product)
○ Update Product: ProductManager.updateProduct(Product)
○ Delete Product: ProductManager.deleteProduct(int productId)
○ Retrieve Product: ProductManager.getProduct(int productId)
○ List All Products: ProductManager.getAllProducts()
○ List Seller Products: ProductManager.getSellerProducts(String seller)
Outputs
1. Product Database State
○ ArrayList<Product> containing all current products
○ Each product with complete details (id, name, seller, price, etc.)
2. Response Messages
○ Success: Product added with ID #[id]
○ Success: Product updated successfully
○ Success: Product deleted successfully
○ Error: Product not found
○ Error: Invalid product data
3. Real-Time Updates to UI
○ ProductCatalog table refreshed with new product
○ Price updates immediately visible to buyers
○ Deleted products removed from all views
○ Stock changes reflected instantly
Processing
1. Add Product Process
a. Step 1: Validate input (name not empty, price > 0, valid category)

=== PAGE 5 ===
b. Step 2: Generate unique product ID (getNextProductId())
c. Step 3: Create Product object with provided data
d. Step 4: Add to productDatabase ArrayList
e. Step 5: Call saveData() for persistence
f. Step 6: Return product with assigned ID
2. Update Product Process
a. Step 1: Validate input (product ID exists, valid data)
b. Step 2: Find product by ID in productDatabase
c. Step 3: Update fields (name, price, stock, etc.)
d. Step 4: Trigger updateProduct(product)
e. Step 5: Call saveData() for persistence
f. Step 6: Return success message
3. Delete Product Process
a. Step 1: Validate input (product ID exists)
b. Step 2: Locate product in productDatabase
c. Step 3: Remove from ArrayList
d. Step 4: Call saveData() for persistence
e. Step 5: Notify all modules to refresh
f. Step 6: Return success confirmation
4. Product Retrieval Process
a. Step 1: Request specific product or product list
b. Step 2: Query productDatabase
c. Step 3: Return copy of product(s) to prevent external modification
d. Step 4: Return empty list if no products found
5. Synchronization Process
a. Step 1: ProductCatalog calls getInstance()
b. Step 2: Gets reference to same ProductManager instance
c. Step 3: Calls getAllProducts() or getSellerProducts()
d. Step 4: Receives current product data
e. Step 5: Refreshes table with latest data
PreConditions
1. ProductManager singleton must be initialized before first use
○ Must occur in ProductCatalog constructor
○ Must occur in ShoppingCart constructor
○ Must occur in OrderProcessing constructor
2. Product data must be valid
○ Name: Non-empty, 1-100 characters
○ Price: Numeric, minimum $0.01

=== PAGE 6 ===
○ Stock: Non-negative integer
○ Category: Valid enumeration value
3. Seller must exist in system
○ Seller ID must match authenticated user
○ Seller must have active account
4. Database must be accessible
○ ProductManager must be able to read/write data
PostConditions
1. After Add Product:
a. Product exists in productDatabase
b. Product has unique ID
c. Product visible to all buyers immediately
d. UI components refreshed with new product
2. After Update Product:
a. Product fields updated in productDatabase
b. Changes visible to all users
c. Buyers see new price/stock immediately
d. No duplicate products created
e. Product history maintained (if applicable)
3. After Delete Product:
a. Product removed from productDatabase
b. Product no longer visible in catalog
c. Buyers cannot add to cart
d. All references cleared
e. Change propagated to all modules
4. After Retrieve/List:
a. Data returned in consistent format
b. No modifications to original data
c. Null/empty safely handled
d. Performance within acceptable limits
Exceptions
1. Invalid Product Data
○ Condition: Price < 0 or Name is empty
○ Action: Reject with error message
○ Message: "Invalid product data: Price must be positive"
○ Recovery: Return to product form with error highlighted
2. Product Not Found

○ Condition: Attempting to update/delete non-existent ID
○ Action: Throw ProductNotFoundException
○ Message: "Product with ID [id] not found"
○ Recovery: Refresh product list and notify user
3. Duplicate Product Name (per seller)
○ Condition: Seller tries to create product with same name
○ Action: Allow with warning (different versions permitted)
○ Message: "Similar product already exists. Continue?"
○ Recovery: Show confirmation dialog
4. Unauthorized Seller
○ Condition: Seller tries to edit another seller's product
○ Action: Deny with access error
○ Message: "You cannot modify another seller's product"
○ Recovery: Redirect to seller's own products
5. Database/Persistence Error
○ Condition: Cannot write to database
○ Action: Catch exception, notify user
○ Message: "Failed to save product. Please try again."
○ Recovery: Retry mechanism or offline mode
6. Concurrent Modification
○ Condition: Multiple users modify same product
○ Action: Last write wins (for Sprint 2 simplicity)
○ Message: "Product was modified by another user. Refreshing..."
○ Recovery: Reload and show updated data
